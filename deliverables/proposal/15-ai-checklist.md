## 15. AI checklist

Status is Planned before the tool exists, then Yes, Partial or No. Every Yes names evidence that someone can open.

At spec stage every row is Planned. The evidence column points to the approved spec, which says what we will build and is not proof that it works. Rows move to Yes, Partial or No only after G5, when someone has opened the real tool or its tests.

| Area | Question | Our answer | Evidence | Status |
|---|---|---|---|---|
| Accountability | Is a named person accountable for what leaves the tool? | The Business Analyst is accountable for the MoM and decides what is sent [A-04]. The tool sends nothing. In a pilot, the sponsor would name the owner of the tool itself (11.2). The BA is a role, not yet a named person per MoM, and the Audit trail does not record the BA's name | 9.4, 6.4, A-04, FN-03 | Planned |
| Responsibility | Is it clear what AI does and what people do? | Yes by design. AI reads the transcript and drafts items. Rules check the AI. The BA decides on every item and fills gaps with the attendees. Each result carries an AI or Rule badge, and the file says "Draft prepared with AI and reviewed by the Business Analyst." | 9.1, 6.4, FN-04, SCR-01 | Planned |
| Human oversight | Must a person decide before any AI result is used? | Yes by design. Nothing is final until the BA chooses Accept, Edit or Reject. Items not yet decided are marked "Not reviewed" in the file, not hidden. The download is not blocked, so a BA can still send undecided items. The BA decides when to run the draft | FN-03, FN-04, 9.4 | Planned |
| Auditability | Can we show who decided what, with which prompt and model? | Partly by design. The Word file's Audit trail records the prompt version, model, run time, export time, and each item's decision and decision time, including rejected items [A-13]. It records the BA's decisions but not the BA's name. Nothing is stored by the tool at Level 1 [A-11], so the file is the only record. Items removed by the checks appear only as counts on screen | FN-04, A3.3, L-04 | Planned |
| Transparency | Can users tell AI results from rule results and demo data? | Yes by design. Items show an AI badge, gap flags show a Rule badge, values the BA typed show "Entered by BA", and Demo mode shows "Demo mode: sample data, no AI" in the header and the Audit trail. Demo samples were prepared by hand [A-15, A-17], and the presenter says so | SCR-01, FN-05, FN-04 | Planned |
| Accuracy | How do we catch wrong or invented results? | Four layers: the format check, the quote check (items with no matching quote are removed), the name and date check (values not in the transcript become "Not stated"), and the BA's review against each quote. None can detect a missed item, and the name and date check does not prove the right person was chosen (L-02, L-03). Accuracy on real transcripts has not been measured | FN-02, A-16, L-02, L-03, 8.3 | Planned |
| Security | Are keys protected and access limited? | The AI key is held only in server settings, never in browser code. An access code is required and wrong or missing codes return 401. There is one shared code and no individual sign-in at Level 1, so access is limited, not personal (R-05). No security review has been done | A3.1, FN-01, R-05 | Planned |
| Data privacy | What data is used, where does it go, and what's kept? | Fictional text only, now. In real use, a pasted transcript goes from the browser through a Vercel function to the AI provider and back, and the tool stores nothing and logs no transcript text. The provider's own retention and terms are unchecked and decide whether real data is allowed (11.2, R-02) | 9.3, A1.3, A-11, 11.2 | Planned |
| Fairness | Could results disadvantage a person or group? | It could. The tool assigns actions and decisions to named people. A wrong or missing owner puts work on the wrong person, and a transcript that is poor or in another language may be handled worse (L-08). The checks only test wording, so the BA must check each owner against its quote. We have not tested for bias | FN-02, FN-03, L-02, L-08 | Planned |
| Reliability | What happens when the AI or network fails? | A plain message says nothing was changed, the transcript stays in the box, and Demo mode is offered. There is one AI call per run and no automatic retry. Demo mode needs no server, no AI and no internet once the page has loaded. Live reliability has not been measured | FN-01, FN-05, A3.4 | Planned |
| Cost control | What stops unexpected spending? | Empty and oversize input is rejected before any AI call (limit 20,000 characters [A-12]), each run makes one AI call with no retry, and an access code limits who can run it. There is no per-person quota and no cost estimate [A-19]. A spending limit at the AI provider is not in the spec and should be set before any shared use | FN-01, A3.4, A-19, R-05 | Planned |
| Compliance | What approvals are needed before real use? | Approval of the AI provider and its data terms, approval of the hosting, a data classification decision for real transcripts, a named owner and support, and any company rules on records and personal data. We have not checked which company policies apply [A-20] | 11.2, 9.3, A-20 | Planned |
